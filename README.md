# Headcount

Ratio-aware staff scheduling for childcare centers. Headcount reads the attendance and timecard
reports a center already exports, forecasts how many children will be in each room every
15 minutes, works out the staff North Carolina law requires, and builds the week's schedule.
When someone calls out, it repairs the day.

**Live demo:** https://YOUR-USERNAME.github.io/headcount/  (replace after turning on GitHub Pages)

> All data in this repository is fictional. The sample center, children, staff and "current
> schedule" were generated by `generate_sample_data.py`. The savings figures the demo
> shows illustrate the mechanism and are not evidence.

## Run it on your computer

Browsers block a page from loading files when it is opened by double-click, so start a small
local server from this folder:

```
python3 -m http.server 8000
```

Then open http://localhost:8000.

## Run the tests

```
node engine.test.js
```

No packages to install. The tests cover CSV reading, column matching, the North Carolina
ratio rules, room combining, shift building and call-out repair.

## How the schedule is built

1. **Import.** Any CSV with a room, a date, a time in and a time out. Columns are matched by
   name, and anything unmatched can be set by hand.
2. **Forecast.** For each weekday, plan to the busiest day seen in the history, plus a safety
   buffer of children per room.
3. **Requirement.** Children in the room divided by the legal ratio, rounded up. Same-age rooms
   may combine before 8:30am and after 4pm when the group fits the legal maximum size.
4. **Shifts.** The requirement curve is sliced into shifts of 3 to 8.5 hours, with break relief
   added around midday.
5. **Test.** The most recent week is held back. Both schedules are replayed against the children
   who actually attended that week, and minutes below ratio are counted.
6. **Call-out repair.** Stretch colleagues' shifts (up to two hours), then borrow from a group
   with spare cover, then report the exact hours that still need a substitute.

See `ASSUMPTIONS.md` before relying on any number this produces.
